# 高度预测中途归零对比

## 结论

8 月旧版日志中，高度预测开始输出非零值后，没有出现过“非零 -> 0 -> 非零”的中途断点。但这不等于旧版气压数据更干净，主要原因是两版程序对异常气压样本的处理方式不同。

当前版本增加了气压速度与 IMU 速度的一致性门限。两者差值超过 `20 m/s` 时，气压估计器立即失效，高度预测被明确写为 0；之后要连续收到 3 个合格气压样本才恢复。旧版没有这个门限和恢复计数，且速度更新无效时直接返回，保留上一次预测值，因此图上看不到归零。

## 日志证据

| 日志组 | 有非零预测的日志数 | 中途归零段数 | 出现归零的日志数 |
| --- | ---: | ---: | ---: |
| 2026-08 旧版 | 10 | 0 | 0 |
| 2026-10 当前版 | 8 | 13 | 7 |

当前版 13 次中途归零时：

- 所有记录的 `barometer_valid` 都为 1，气压样本年龄为 4-17 ms，不是 BMP280 掉线或样本过期。
- 由相邻气压高度样本反算的速度，与 IMU 速度相差 21.11-754.45 m/s，全部超过当前 `20 m/s` 门限。
- 例如 `flight_log_20261002_launch2_com9` 在 19.848 s 的相邻气压高度跳变对应 784.00 m/s，而 IMU 速度为 29.55 m/s，差值 754.45 m/s。这是明显的气压冲击或瞬时异常样本。
- 归零持续时间多为 0.12 s，与 40 ms 气压周期下连续 3 个合格样本的恢复策略一致。更长的 0.36-0.72 s 间隔表示中间又收到了不合格样本，恢复计数被重置。

完整统计见 `altitude_prediction_dropout_summary.csv`，每次归零的时间、恢复时间和速度差见 `altitude_prediction_dropout_events.csv`。

## 源码差异

旧版 `Hardware/AltitudeControl.c`：

- 气压高度一旦到达更新周期，就直接计算气压垂直速度，没有与 IMU 速度做合理性比较。
- `velocity_valid == 0` 时直接返回，没有把 `predicted_apogee_m` 清零，因此会保留上一次值。

当前 `Hardware/AltitudeControl.c` 和 `Hardware/RocketConfig.h`：

- `ROCKET_ALTITUDE_BARO_STALE_MS = 120`，过期气压样本不参与估计。
- `ROCKET_ALTITUDE_BARO_IMU_SPEED_GATE_MPS = 20.0`，原始气压速度与 IMU 速度相差超限时使气压估计器失效。
- `ROCKET_ALTITUDE_BARO_RECOVERY_SAMPLES = 3`，要求连续 3 个合格样本后再恢复。
- 气压估计器失效时，明确设置 `predicted_apogee_m = 0` 和 `prediction_valid = 0`。

## 判断

以前“不归零”主要是显示和失效处理策略不同，不是以前没有气压冲击。当前归零是保护机制拒绝不可信气压样本的结果，比直接用异常样本计算预测高度更保守。如果只想让曲线不掉到 0，应将“最后一个有效预测值”作为显示值，同时保留 `prediction_valid = 0` 作为无效标记；不应让无效显示值重新参与控制。
